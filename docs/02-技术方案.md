# 技术方案

## 方案

使用原生 HTML、CSS、JavaScript 构建单页网站。

## 文件职责

- `index.html`：页面结构与表单。
- `styles.css`：布局、颜色与响应式样式。
- `app.js`：任务的新增、筛选、完成、删除、备注和本地保存。

## 数据保存

使用浏览器 `localStorage` 保存任务。它不需要账户或服务器，但仅保留在当前浏览器和设备中。

## 任务字段

- `id`：唯一标识。
- `title`：任务名称。
- `priority`：低、中、高。
- `dueDate`：截止日期，可为空。
- `note`：任务备注，可为空。
- `category`：任务分类，可为空；有值时只能是 `study`、`work` 或 `life`。
- `completed`：是否完成。
- `createdAt`：创建时间。

## T-02 任务分类设计

### 输入控件

- 在新增任务表单中增加一个原生下拉框，放在“优先级”和“截止日期”之间。
- 控件使用 `id="task-category"`、`name="category"`，标签为“分类（可选）”。
- 第一个选项为“未选择”，其值为空字符串；另外三个固定选项分别为：`study`（学习）、`work`（工作）、`life`（生活）。
- 分类不是必填项，提交空值时任务正常创建。

### 列表展示

- 已选择分类的任务，在任务名称下方现有的优先级和截止日期信息中展示一个分类标签。
- 分类标签放在优先级标签之后、截止日期之前，使用与优先级标签相近的紧凑样式，以便一眼区分任务所属分类。
- 未选择分类或旧任务没有分类字段时，不渲染分类标签，也不显示“未分类”文字。

### 数据与兼容

- 新增任务对象保存 `category` 字段，值为下拉框选中的固定代码或空字符串。
- 页面加载旧任务时不改写本地数据，也不补填 `category` 字段；渲染时将缺失、空值或不在固定选项内的值都按“无分类”处理。
- 这样旧任务仍可完成、删除和保存；本次只新增字段，不删除或重建已有任务数据。

### 预计影响文件

- `index.html`：增加分类下拉框，以及任务模板中的分类展示节点。
- `styles.css`：调整桌面表单列布局，并增加分类标签样式；手机端继续沿用纵向表单布局。
- `app.js`：读取下拉框、在新增任务时保存 `category`、渲染有效分类标签，并对旧数据做缺失字段兼容。
- `docs/03-任务清单.md`、`docs/04-测试记录.md`、`docs/05-变更记录.md`：记录开发状态、测试结论和变更。
