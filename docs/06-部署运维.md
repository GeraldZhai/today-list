## 推荐部署方式

本项目没有后端和构建步骤，使用 GitHub Pages 托管。首个版本从仓库默认分支的根目录发布，不增加构建工具。

## 发布文件

网站运行只需要以下文件：

- `index.html`
- `styles.css`
- `app.js`

`docs/` 和 `AGENTS.md` 是项目管理资料，不是网站运行必需文件。

## 上线步骤

1. 保存本次发布版本和发布日期。
2. 将三个网站文件发布到项目经理确认的静态托管平台。
3. 打开公开网址，进行一次最小线上检查：页面加载、新增任务、刷新保存。
4. 记录公开网址、部署结果和回滚点。
5. 删除线上检查产生的测试任务。

## 回滚方案

1. 每次发布前保留上一个可用版本。
2. 如果页面无法加载或核心功能不可用，立即恢复上一个版本的三个网站文件。
3. 回滚后重新检查页面加载、新增任务和已有任务显示。
4. 在变更记录中写明故障原因、影响时间和后续修复任务。

## 数据与域名风险

任务数据保存在浏览器 `localStorage` 中，不在服务器上。它有以下限制：

- 不同设备和浏览器之间不会同步。
- 清除网站数据会删除任务。
- 从本地网址切换到公网域名时，本地任务不会自动带过去。
- 更换公网域名后，旧域名下的任务不会自动出现在新域名。

因此，部署网站不会替用户备份任务。后续应单独规划“任务导出与导入”功能，再考虑长期使用或更换域名。

## 日常运维

### 每次发布后

- 检查公开网址能否打开。
- 检查浏览器控制台没有阻止页面使用的错误。
- 在桌面和手机各完成一次新增与刷新测试。
- 确认 HTTPS 正常，页面没有加载不安全资源。

### 每月检查

- 确认网站仍可访问。
- 检查托管平台是否有失败或异常部署。
- 确认公开网址和部署平台没有变化。
- 回顾是否需要任务导出、备份或云端同步。

## 故障处理

| 级别 | 情况 | 处理方式 |
| --- | --- | --- |
| 紧急 | 页面打不开或任务功能完全不可用 | 立即回滚到上一可用版本，再排查原因 |
| 重要 | 某个功能不可用，但其他功能正常 | 记录问题，停止继续发布，交回开发修复 |
| 一般 | 样式、文字或非核心体验问题 | 建立新任务，安排到下一次迭代 |
